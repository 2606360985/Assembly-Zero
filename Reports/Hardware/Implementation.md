## 基线与续作修复
原始修改清单见 `BaselineStatus.txt`；保护文件核验见 `ProtectedFiles-Resume.json`。EP03 两个场景及 GraphicsSettings、QualitySettings 均与初始 SHA256 一致。

旧包及最初新包均在场景进入前原生崩溃。输入初始化日志只是最后输出，不能据此归因输入系统。2026-10-21 使用安装目录自带 PDB 解析 crash.dmp，实际调用栈为 `Material::SetTextureInternal → DrawQuad → DrawSplashScreenBackground → DrawSplashScreen`；见 `NativeCrashSymbols.txt`。构建报告同时存在 SplashScreenCache 加载错误。新包构建临时关闭启动画面，构建结束恢复原项目设置；已证实可进入游戏。单个损坏的派生缓存备份到 `Temp/SplashScreenCache-corrupt-20261021.bin`，未清理用户资源或场景。

恢复走查原先在输送到料前检查余额，导致误失败；改为等待真实加工扣款，仍不注入现金。交互测试补充独立输入配置，忽略编辑器焦点，但不改变产品输入设置。暂停菜单增加全屏点击遮挡。首单取消/超期后生成新报价，恢复经营后仍能进入静音版；首单后的目标提示指向静音版；设备采购按钮按实际缺口选可购买物料，静音版不会误选标准散热器。

## 运行与复验
Windows 包：`Builds/Hardware/AssemblyZeroHardware.exe`（需保留同目录全部依赖）。编辑器场景：`Assets/_AssemblyZero/Scenes/Hardware_Business.unity`。

在项目根目录运行：
```powershell
& ./Builds/Hardware/AssemblyZeroHardware.exe --hardware-verify --hardware-short -screen-fullscreen 0 -screen-width 1920 -screen-height 1080
```
去掉 `--hardware-short` 会在初始和扩建状态各预热30秒、采样120秒。验证模式不读取或写入用户存档；不要使用 `-batchmode` 或 `-nographics` 来验收真实渲染。报告写入工作目录下 `Reports/Hardware/实际宽度x高度`。

## 验收边界与问题分级
- P1：人工完整游玩尚未执行。自动命令走查、合成键鼠和截图各自证明不同范围，不能合并宣称玩家已验收。仍需玩家按 README 完成配送/自提两条路线，确认缺料引导可理解、愿意继续经营。
- P2：场景属于简化工业原型，与参考图的资产密度、材质和光照精度有明显差距。默认相机能看到产线；采购站沿北向道路可达，不在默认整厂构图内。
- 已确认边界：订单/采购采用固定配置；无自由 SKU、动态市场或自动补货。未实施本轮边界外的新品类、联网或 Steam。
- P2：历史全量 PlayMode 中 EP01/EP02 的 Build Profile 场景缺失未在本轮处理；现有 EP01–EP03 场景未改动。保留领域回归结果不等于重跑所有旧场景的画面验收。
- P3：旧代码存在 Unity 6 弃用 API 警告，具体条目保留在 Build-BeforeSplashFix.txt；不为消除警告改动受保护旧演示代码。

只有独立包画面、完整可玩、性能和人工理解度分别得到确认，才进入后续产品配置与二厂分工阶段。

续作过程中 Unity 提示恢复上次场景备份，已选择保留到 Assets/_Recovery，未覆盖正式场景；该目录作为恢复资料保留，不属于切片运行资源。

HUD 迭代对比：Hud-EarlyEditor.png 是前一轮编辑器初版截图，分辨率与最终独立包不同；最终界面见分辨率目录。旧 EP04 原生包启动失败，不能将其黑屏当作有效的旧界面验收图。
