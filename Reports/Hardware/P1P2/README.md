# P1 / P2 迭代审计与验收

日期：2026-11-04。基于本次开始时工作区中尚未提交的 P1/P2 实现继续开发，保留原有修改。

## 审计结论

原实现已包含：统一显卡物料链、Goods 的 SKU/世代/档位属性、检测 A/B/C 分档及合同筛选、研发实验室、递增的世代研发项目、旧卡残值、SKU 名称/显存/散热/配色/价格设计、程序化模型和设计器预览。

原实现尚缺：核心体质和目标市场选择、不同世代真正隔离的生产、换代停产窗口、独立于玩家研发的行业换代节奏、C 档降级包装入口、独立风扇/卡长/背板选项、旧正式版存档迁移。另发现无合适 SKU 仍生成高性能需求订单、预览使用包装盒而非卡体、初始化时访问尚未创建的 View、存档恢复自动改写首件产品时间等问题。

## 本次补齐

- 物料只匹配基础类型，世代、核心体质、检测档位、SKU/版本跟随货物跨工序和存档流转。新 SKU 和新世代不分配物料 ID。
- 核心采购可选已研发世代与 A/B/C 体质，价格分别为同代主流核心的 125%/100%/80%。混合体质型号可使用任意体质；指定体质型号需要匹配板卡。核心体质影响型号性能和价格；检测后的 A/B/C 为另一层成品质量评级。
- SKU 固定设计时的世代；旧型号不会因为采购新核心自动升级。板卡装配和显卡总装需要工艺改造才能生产新世代，每台默认 120 元、30 模拟秒；先完成在产批次，随后停机，改造进度可存档。保留原有输送接口。
- 旧板卡在换型时按现有改建回收机制局部回仓。没有给开局新增一条全局半成品回仓线路，避免改变教学节拍和推荐位置。
- 完成两张教学合同后，每 30 模拟分钟行业向下一世代推进，玩家不研发也会面临旧卡贬值。教学合同价格、已接受合同和历史结算保持快照。行业时间在暂停时停止。
- 检测 A/B/C 保留订单匹配和分级售价；新增 C 档专用降级包装，优先分走 C 档，A/B 档继续走普通包装。次品返修和丐版路线继续保留。
- 设计器可选已解锁核心世代、体质、显存、散热、目标市场（通用/游戏/矿场/AI/OEM）、配色、风扇数、卡长、背板及价格。风扇、卡长、背板属于外观选项，界面明确标注不影响性能。
- 性价比与上市时口碑形成评测分，目标市场与客户需求决定订单匹配；同类匹配客户优先考虑定向型号。无合适产品不再生成不满足性能条件的报价；维修恢复订单优先使用当前产线型号。
- 预览显示显卡卡体，输送货物按实际货物世代和档位显示；离开产品页关闭预览摄像机。
- 支持正式 v3/content v2 和上一轮 v4/content v3 存档迁移。旧文件作为读取来源保留，后续保存写入 v4 文件。未来/不匹配战役存档继续拒绝。
- 高世代价格、性能及研发需求采用有界整数增长，防止溢出为负数；世代编号和项目继续递增。仍使用现有 32 位账户上限。

## 操作入口

1. 开局按原教学交付首单及网吧单。
2. 「研发」建实验室、开始下一代研发；完成后在该页改造本厂装配设备，也可选中设备逐台改造。
3. 「产品」选择新核心世代与体质等参数并上市，在型号卡点击「总装改产此型号」。
4. 「采购」或「采购总览」选择 GPU 核心，切换核心世代及体质，核对报价后采购；缺料引导会携带所需世代/体质。
5. 「产品」的 C 档分流按钮建造专门包装机；可通过设备页切换普通包装、次品包装和 C 档包装。
